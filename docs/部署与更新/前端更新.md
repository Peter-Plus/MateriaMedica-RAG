# 前端更新

适用于修改 `client/` 下的共用界面、交互或默认服务器地址。**每次交付前端更新，都要同时生成并确认 Windows 便携 ZIP**。客户端通过 ZIP 分发；网页版需将构建的静态文件更新到 Ubuntu 服务器。仓库根目录 `AGENTS.md` 也将打包列为 Codex 更新前端时的交付步骤。

## Windows 客户端更新

在 Windows PowerShell 执行，先将 `xxx\BCRAG` 换成自己电脑上的项目目录。`npm run make` 已配置 Electron Forge 的 ZIP maker，会直接生成 ZIP，**不需要再手动压缩**：

```powershell
cd "xxx\BCRAG\client"
npm run make
$version = (Get-Content .\package.json -Raw | ConvertFrom-Json).version
Get-ChildItem ".\out\$version\make\zip\win32\x64\*.zip"
```

如在新电脑上首次构建，或依赖有变化，先执行 `npm ci`。要发布一个新的版本号，可先执行 `npm version patch --no-git-tag-version`，再执行上述命令。最后一行必须列出新 ZIP；产物位于 `client/out/<版本号>/make/zip/win32/x64/`。解压后运行 `BCRAG.exe`，无需浏览器。

客户端默认连接 `https://brag.worldlinesite.com`。0.1.4 起，左下角“设置”内提供“开启本地调试”开关，开启后才显示地址和端口；关闭并保存即可恢复线上服务。升级时旧版自定义地址仅保留为调试地址候选，不会自动开启调试；新版已保存的调试开关会在重启后保留。实际连接改变时需要重新登录，未改变连接的保存不会退出账号。“打开网页版”通过系统浏览器打开线上页面。真实模型 Key 只保存在服务器，不放进客户端。后端 API 路由或响应格式变化时，先确认新版客户端与后端兼容。

## 网页更新

### 客户端下载附件

网页“下载 Windows 客户端”指向 [GitHub 最新版附件](https://github.com/Peter-Plus/MateriaMedica-RAG/releases/latest/download/BCRAG-Windows-x64.zip)。ZIP 放在公开仓库 `Peter-Plus/MateriaMedica-RAG` 的 Releases 附件中，由 GitHub 提供下载，项目服务器只提供网页与 API。

更新客户端时，将构建好的 ZIP 以固定附件名 `BCRAG-Windows-x64.zip` 上传到对应版本的 Release，并将该正式版本设为 Latest。请使用 Release 独立的二进制附件区域；附件上传完成后再发布。每个新版本都保留这个附件名，即可沿用网页链接；不要把 ZIP 提交到源码目录，也不要上传到发布说明编辑框的普通附件区域。

### 发布网页

访问地址：[https://brag.worldlinesite.com/](https://brag.worldlinesite.com/)。网页使用同域 `/api/`，与客户端共用账号、历史和知识库；密钥仍仅保存在后端。页面刷新可恢复当前标签页登录。

在 Windows PowerShell 执行（将 `xxx\BCRAG` 换为自己的目录）：

```powershell
cd "xxx\BCRAG\client"
npm ci
npm run test:web
npm run build:web
cd ..
tar -czf deploy/bcrag-web-update.tar.gz -C client/dist/web .
scp deploy/bcrag-web-update.tar.gz deploy/publish-web.py ubuntu@129.226.116.120:/home/ubuntu/
ssh ubuntu@129.226.116.120
```

登录现有服务器后执行：

```bash
sudo python3 /home/ubuntu/publish-web.py /home/ubuntu/bcrag-web-update.tar.gz
curl -I https://brag.worldlinesite.com/
curl -fsS https://brag.worldlinesite.com/api/health
```

发布脚本仅适用于当前已有的 `brag` Nginx 站点：静态文件写入 `/var/www/bcrag/web-releases/`，通过 `/var/www/bcrag/web` 链接切换版本。脚本备份并修改网页入口，保留已有证书与 API 代理，配置验证失败会回滚。不上传 `node_modules`、`.env` 或数据库，也不重启 Python 后端。

`npm run test:web` 使用本地模拟 HTTP 接口，验证网页登录、注册、刷新恢复、历史、Markdown、退出、失效会话和手机布局，不产生模型费用。新回答与历史回答复用 Electron 的页面代码。

## 页面与 Markdown 验证

0.1.2 优化了登录、聊天和出处区域的排版，并支持 AI 新回答及历史回答中的 Markdown 标题、列表、加粗、引用、表格和代码块。解析库与过滤库随客户端打包，无需访问外部 CDN。用户问题和古籍摘录保持原文显示；回答中的 HTML 不执行，远程图片不加载，HTTP/HTTPS 链接使用系统浏览器打开。

在 `client` 目录运行 `npm test`，会通过隐藏的 Electron 窗口检查 Markdown、历史消息、危险内容过滤、出处、等待状态、失败重试、侧栏异常和最小窗口布局。测试使用模拟接口，不连接线上服务、不消耗模型额度；截图保存在 `data/ui-check/`，不要提交到版本库。真实登录、模型生成及系统浏览器打开链接需另行人工验证。

如构建卡在 Electron 下载，可将环境变量 `BCRAG_ELECTRON_ZIP_DIR` 设为本机已缓存的 Electron ZIP 所在目录，再运行 `npm run make`。该目录必须包含与安装版本、平台和架构一致的文件，例如 `electron-v44.5.1-win32-x64.zip`；不设置时仍使用默认下载流程。
