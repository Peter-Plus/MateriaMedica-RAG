# 本地运行与调试

适用于在自己的 Windows 电脑上运行 Electron 客户端、Python 后端和 SQLite 知识库。需要 Python 3.8+、Node.js 22+ 和 npm。以下命令使用 PowerShell；将 `xxx\BCRAG` 换成自己电脑上的项目目录。

## 1. 配置本地模型 Key

进入项目根目录：

```powershell
cd "xxx\BCRAG"
```

首次配置时，将根目录 `.env.example` 复制为同目录下的 `.env`；已有 `.env` 时直接编辑，不要覆盖。用文本编辑器填写其中的 `BCRAG_API_KEY`：

```dotenv
BCRAG_API_KEY=你的真实Key
```

`.env` 与 `README.md` 同级，不放进 `client/` 或 `server/`，文件名不要变成 `.env.txt`。默认配置使用阿里云百炼北京区兼容接口，Key 应与接口地域匹配。模型生成需要联网，未配置有效 Key 时无法生成问答，但可以进行本地关键词检索。

`.gitignore` 已忽略 `.env`；新建且未被 Git 跟踪的 `.env` 不会随正常提交和 push 上传。不要强制添加，也不要把真实 Key 写进 `.env.example` 或客户端。

## 2. 准备知识库

可选安装完整的简繁转换依赖；未安装时会使用内置常见字回退表：

```powershell
python -m pip install -r server/requirements.txt
```

首次运行或尚未导入古籍时，从项目根目录执行：

```powershell
python -X utf8 -m server.ingest "文献/原文/本草綱目-全文.txt"
```

如果拷贝的 `data/bcrag.sqlite3` 已包含知识库，可直接检查检索。相同文档内容未变时，重复导入不会重建索引。

```powershell
python -X utf8 -m server.search "人参有哪些记载"
```

此检索检查不需要模型 API Key。向量生成是可选步骤，会调用模型接口并产生用量，详见 [RAG更新](RAG更新.md)。

## 3. 启动本地后端

在项目根目录执行，并保持该终端运行：

```powershell
python -X utf8 -m server.api
```

默认健康检查地址为 <http://127.0.0.1:8000/api/health>。修改 `.env` 或后端代码后，在该终端按 `Ctrl+C` 停止，再执行上述命令重启。

## 4. 启动客户端并连接本地后端

另开一个 PowerShell 终端：

```powershell
cd "xxx\BCRAG\client"
npm install
npm start
```

依赖已安装且没有变化时，后续可直接执行 `npm start`。

客户端首次启动默认连接 `https://brag.worldlinesite.com`。在“服务器设置”中将地址改为 `http://127.0.0.1:8000` 并保存，再注册或登录本地账号，检查知识库、问答和出处展示。已有客户端会沿用保存的服务器地址，请核对登录页显示的“当前服务器”。本地后端使用自己的账号和对话数据库，线上账号未必能直接登录本地服务。

如果只想使用线上服务，将地址设为 `https://brag.worldlinesite.com` 即可；在该服务可用且已配置 Key 的前提下，本机无需启动后端或配置 Key。公网服务器地址必须使用 HTTPS。

## 5. 调试与排查

- 无法连接服务器：确认客户端地址是 `http://127.0.0.1:8000`、本地后端仍在运行，并检查健康接口能否访问。
- 后端能连接但无法生成回答：检查根目录 `.env` 中的 Key、接口配置，以及修改后是否重启了后端；结合后端终端报错定位问题，不要分享真实 Key。
- 检索不到原文：先运行第 2 步的检索命令，确认古籍已导入当前本地知识库。
- 修改客户端后：关闭客户端并重新执行 `npm start` 查看效果。

在 `client` 目录执行 `npm test` 可运行前端模拟接口测试；测试不连接线上服务、不消耗模型额度，截图保存在 `data/ui-check/`。详细覆盖范围见 [前端更新](前端更新.md)。真实登录和模型生成需要另外人工验证。

客户端交付打包步骤见 [前端更新](前端更新.md)；新增古籍见 [文献更新与扩展](文献更新与扩展.md)。
